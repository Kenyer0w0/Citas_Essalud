GUÍA PARA EL EQUIPO DE DESARROLLO

Integración del backend

Contrato inicial para conectar la interfaz con la API Spring Boot.

Contrato de servicios pendiente
⌘
Autenticación preparada para la API del proyecto

Confirma las rutas y DTO propuestos con el equipo backend. El catálogo, las agendas y las reservas requieren sus servicios conectados antes de operar.

01

Autenticación

Emitir un JWT de corta duración y devolver el rol autorizado del usuario.

POST /api/auth/login POST /api/auth/registro GET /api/auth/me
02

Catálogo y agenda

Exponer solo servicios habilitados y turnos publicados para la sede del asegurado.

GET /api/especialidades?reservaDirecta=true GET /api/medicos?especialidadId=... GET /api/horarios/disponibles?medicoId=...&fecha=...
03

Reservas y cancelación

La API debe validar cobertura, propiedad, ventana de cancelación y evitar doble reserva.

POST /api/citas GET /api/citas/mias PATCH /api/citas/:citaId/cancelar
04

Vistas por rol

Proteger los datos y acciones en servidor; ocultar botones en el cliente no reemplaza autorización.

GET /api/medico/agenda?fecha=... GET /api/admin/citas?fecha=...

REGLAS DE RESPUESTA

Validaciones del servidor

REQUERIDO
  • 401Token ausente, inválido o expirado.
  • 403El rol no puede acceder a ese recurso.
  • 409Turno ocupado o conflicto de reserva.
  • 422Cobertura no vigente o datos de solicitud inválidos.
  • 503Servicio de validación temporalmente no disponible; no crear la cita.

CONFIGURACIÓN

Conectar el servicio

LOCAL
  1. Permitir CORS desde http://localhost:4200 durante desarrollo.
  2. Configurar la URL base en src/app/api.config.ts.
  3. El login utiliza DNI y contraseña; el registro requiere DNI, nombres, correo y contraseña.
  4. Conectar catálogos, agendas, citas y permisos con ApiService.
  5. Probar permisos y conflictos con cuentas y datos ficticios.
Seguridad y datos

Usar exclusivamente datos de prueba hasta verificar la protección de datos y habilitar HTTPS. Nunca solicitar claves de otros servicios. Las reglas de cobertura, adscripción, disponibilidad y permisos se deciden en el servidor.
